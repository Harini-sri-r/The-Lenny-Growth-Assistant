# Architecture

## Request flow
The React/Vite client creates a persistent browser workspace ID and calls FastAPI under `/api/v1`. Chat sessions, user and assistant messages, timestamps, grounding state, citations, and generated artifacts are stored in PostgreSQL through SQLAlchemy. Alembic owns schema changes; apply `alembic -c backend/alembic.ini upgrade head` before serving the API. A SQLAlchemy database exception returns a safe 503.

For standard RAG chat, the service embeds the query through Ollama, retrieves cosine-ranked ChromaDB passages, filters by configured minimum similarity, and calls the selected LLM adapter. Ollama is the default. OpenAI and Google Gemini use optional cloud adapters and fall back to Ollama when credentials are absent or a cloud request fails. The system prompt limits answer evidence to retrieved passages and source labels not present in the retrieved set are removed. Empty retrieval returns an explicit insufficient-evidence response without calling the LLM.

The default `AGENT_FRAMEWORK=rag_service` and `LLM_PROVIDER=ollama` keep chat and Ship 30 generation local, with no cloud credentials. Ship 30 uses the configured provider directly, a full essay target, an adjustable output-token budget, and up to three bounded continuations when needed. Each continuation receives the current citation-validated word count and remaining target; the combined essay must pass the same retrieved-source citation validation and minimum-length check as RAG answers before persistence. Per-attempt diagnostics record provider, model, raw and validated counts, token usage, finish reason, and truncation without prompts or essay content. Unlike chat, Ship 30 does not silently switch to Ollama after a Gemini request fails; its diagnostics record selected and actual provider identities. Local HTML artifacts wrap the validated Markdown in a self-contained HTML document.


When `AGENT_FRAMEWORK=pi_coding_agent`, FastAPI retrieves and labels passages with the existing Chroma/Ollama pipeline, then invokes Pi through its documented one-shot JSON event stream (`--mode json --no-session --no-tools`). The adapter extracts the terminal assistant message and validates citations against only the retrieved references before returning. `LLM_PROVIDER=gemini` uses Pi's Gemini provider and `GEMINI_API_KEY`; `LLM_PROVIDER=ollama` uses a compatible Ollama endpoint configured in Pi's user `models.json` and model ID matching `OLLAMA_MODEL`. Pi calls do not fall back to the Python provider adapter. This keeps existing retrieval, PostgreSQL session and artifact persistence, and viewer paths intact.

When `AGENT_FRAMEWORK=claude_agent_sdk`, chat and Ship 30 use `ClaudeResearchAgent` when an Anthropic API key is configured. It exposes a single read-only in-process MCP tool, `search_transcripts`, to Claude Agent SDK and permits no filesystem or shell tools. For `LLM_PROVIDER=openai` or `gemini` with `AGENT_FRAMEWORK=rag_service`, Ship 30 uses that configured cloud provider directly. Gemini uses the official `google-genai` SDK, configured with `GEMINI_API_KEY` and `GEMINI_MODEL`; missing credentials and provider failures are surfaced as actionable errors instead of switching to Ollama. Regular chat retains its Ollama fallback. Live cloud operation still requires valid provider credentials, project access, and quota.

## Data and configuration
The existing archive remains at `lennys-newsletterpodcastdata-main/`; set `TRANSCRIPTS_PATH` to configure its location. `index.json` supplies document title/type/date and available URL and descriptive metadata. Chunk identifiers are deterministic. On a normal rerun, compatible existing records may be reused; missing or incompatible chunks are embedded and upserted. Stale-record cleanup occurs only after indexing succeeds, so a failed run does not reach cleanup. `--reindex` explicitly clears and rebuilds the Chroma collection. These are implementation behaviors, not evidence that live indexing, reuse, or cleanup has been verified.

The persistent Chroma directory is configurable with `CHROMA_PERSIST_DIRECTORY` and ignored by Git. `.env` secrets and the licensed data directory are also ignored. No absolute developer machine path is required.

## Artifact isolation
Markdown previews are displayed as escaped text. HTML/CSS previews use an iframe with an empty `sandbox` attribute (no scripts or same-origin privileges) and a restrictive Content Security Policy that disables network resources by default. Do not add `allow-scripts` or `allow-same-origin` or inject generated markup into the parent document.

## Operations and limitations
Docker Compose starts PostgreSQL, runs Alembic migrations in the backend container, checks API health, and serves the frontend separately. The frontend image installs exactly from `package-lock.json` using `npm ci`. Backend request logs use JSON fields and intentionally omit request bodies, prompts, transcript passages, and query strings. Browser workspace IDs separate demo histories but are not user authentication; public deployment requires a real identity provider and authorization.
